## v0.9.4 — Tag Sources, Model-Aware Styles & Enhance Max

### New
- **Import your own tag lists (Danbooru / e621 CSV, JSON, plain text).** Tag Library → the new *Tag lists* button. Drop in an a1111-tagcomplete style `name,category,count,"aliases"` CSV (no header), a header CSV in any column order (including e621's `db_export` dump, gzipped or not), a JSON array/map, or one-tag-per-line text. The importer sniffs the shape, lets you fix the column mapping, and asks which **category numbering** the file uses — the same digit means *meta* on Danbooru and *species* on e621, so Danbooru / e621 / merged-list / custom profiles are offered with an auto-guess. Pick a minimum post count (with a live "N of M" readout), which categories to keep, and whether underscores become spaces (on by default; emoticon tags like `^_^` are left alone). Each list is stored separately from the bundled Danbooru data, can be toggled off, reordered (priority on name collisions; the bundled list always wins and just absorbs extra aliases), renamed, updated from a newer file, exported, or deleted. Suggestions from an imported list carry a small source badge. New categories **species**, **lore** and **contributor** get their own colours, and `/fs` / `/fl` join the favourites shortcuts. Favourites and example images set on imported tags live in a sidecar, so re-importing an updated list keeps them. Imported lists — and the favourites you set on their tags — are included in `.vpack` backups and per-list exports (example images are local files and stay behind).
- **Faster autocomplete.** Prefix matches now come from a sorted name index (binary search) instead of a scan over every tag, and the substring / alias passes only run when the prefix pass hasn't already filled the list — so a large imported e621 list doesn't make typing sluggish.
- **Styles can target V4.5 and/or V5.** Style Editor → *Works with* chips (both by default; each list row shows a badge). The STYLES panel, cascade beats and keyboard style cycling only list styles made for the active model, with an "N styles hidden (made for V5)" hint so nothing looks lost; switching models swaps an active style made only for the other family for that family's default — a style marked *default* that targets it, else the bundled Light preset for that family — and never touches one that targets both. Older style files, packs and imports load as "both"; the bundled styles are marked.
- **Enhance "Max" on V5.** A MAX ✨ chip after the scale chips (offered when the source is below 0.8 × NovelAI's 3,145,728 px cap) sends the source at its own size (rounded to multiples of 64, like every request) with `upscaled_enhance: true` and gets it back at 2× (or scaled to ~3.1 MP when 2× would exceed NovelAI's cap); the dimension line shows the predicted size. The numeric scale chips now follow NovelAI's 2× / 1.5× / 1× rule instead of a fixed pair. Verified against the live API on 2026-09-09 (four Opus runs on V5 Full): an 896×1152 source came back as 1564×2011 in ~4 s and a 512×768 source as 1024×1536 — so Max is **2× the source, or the source aspect scaled to the 3,145,728 px cap when 2× would exceed it** (the capped size is not 64-aligned). Max is **charged in Anlas even on Opus**; the V5 allowance was untouched. The charge is the ordinary img2img price of the *output* size × strength × ~1.46 (23 / 27 / 45 / 12 Anlas across the four runs, all reproduced exactly by the app's estimator), so the Anlas figure next to the dimensions is now a fit rather than a guess.
- **Steps and CFG are remembered per model, and a style can carry its own.** Switching between V4.5 and V5 brings back the steps / guidance you last used on each family (never the model defaults — that is still the DEFAULTS button); the memory is kept in the session snapshot and in backups (`model_render_settings`), so it survives with *Remember session* off. In the Style Editor, *Apply custom steps and CFG for this style* pushes those values while the style is selected and restores your per-model values when it is deselected or swapped for a style without an override.
- **Gallery viewer: pin the controls.** A pin button in the viewer's top bar keeps the top/bottom overlays (buttons, prompt, counter) on screen instead of fading them out after three seconds of inactivity. The choice is remembered across sessions and backups; unpin to return to auto-hide.
- **"Copied to clipboard" now appears as a toast at the top-centre of the viewer** instead of a bottom snackbar that covered the action bar.

### Fixes
- **Renaming a style no longer leaves a duplicate behind.** Saving after a rename replaced nothing (the lookup used the new name) and appended a copy instead. The editor now has *Save changes* (overwrite in place) and *Save as new* (a copy, auto-suffixed " (Copy)", " (Copy 2)" … when the name is taken); brand-new styles and duplicates get unique names too.
- **Mobile pinch-zoom on the main screen: fingers on the bottom half of the image after the first pinch.** The advanced-settings panel's animated overflow is now clipped to its slot (it hit-tests before the image) and the preview box takes pointers everywhere, including the letterbox bands around the image. Not yet verified on a device.
- **Save Subfolder Pattern now applies to SD-card / picked-folder exports on Android.** The pattern was only honoured for the app's private copy; an export to a folder chosen in Settings (a Storage Access Framework target) wrote flat into that folder, so images all landed in one place. *Export to Device* after a render, the auto-export, and the gallery's own Export (viewer and bulk) now create the subfolder chain (e.g. `2026/09/07`) under the picked folder — plain or SD card — and `<digits>` counts per subfolder there too, matching desktop. Gallery exports keep each file's existing name; `<prompt>` / `<seed>` come from the image's own metadata and `<album>` is the album being viewed. The device-gallery *album* export is flat by nature and ignores the subfolder pattern; the setting text now says so.
- **Your own steps / CFG edits stick while a style override is selected.** Toggling any other style used to re-apply the override style's numbers over what you had just typed; the override is now pushed when the style becomes active (and again after a model switch), not on every style change.
- **Renaming a style that is currently selected keeps it selected** (and keeps its steps / CFG override) under the new name instead of silently dropping it from the active list.

### Under the hood
- Enhance Max verified against the live API (four Opus runs); `test/live/enhance_max_live_test.dart` reproduces the probe and is skipped without `--dart-define=NAI_TOKEN`. Full suite at 671 tests; analyzer clean; Windows release and Android debug builds verified locally.
